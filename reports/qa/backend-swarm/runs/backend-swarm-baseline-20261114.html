HIGHBlind Trust Proxy (`app.set('trust proxy', 1)`) Susceptible to Client IP Spoofing and Shared Proxy LockoutCONFIGURATION_DEFECTOPEN

backend/src/app.js:30 · VERIFIED confidence: HIGH

Evidence

app.set("trust proxy", 1);

Scenario

The application is deployed behind Caddy, Cloudflare, and Docker bridge network. Trusting 1 hop means Express assumes there is only a single trusted reverse proxy. In a multi-hop edge setup (Cloudflare -> Caddy -> Node), the first hop in X-Forwarded-For is an upstream proxy or an internal container IP (e.g. 172.18.0.x). When express-rate-limit and loginRateLimiter look up req.ip, every user sharing that proxy hop gets bundled under the same IP address. One malicious user triggering brute-force lockouts causes all other legitimate users to be rate-limited and locked out (Denial of Service).

Impact

Global denial of service for all users behind common edge proxies, or rate-limit evasion by spoofing header values if accessed directly.

Reproduction

Send requests with forged X-Forwarded-For: 1.1.1.1, 2.2.2.2. req.ip resolves incorrectly depending on proxy hop count.

Suggested remediation

Configure trust proxy to explicitly trust known internal subnet ranges or loopback, e.g., app.set('trust proxy', 'loopback, linklocal, uniquelocal') or configure Caddy to overwrite X-Forwarded-For with the remote client IP directly.

Regression test

Integration test validating that req.ip accurately extracts client IP when behind Caddy with Docker bridge IPs (172.16.0.0/12).
