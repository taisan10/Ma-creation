HIGHUnhandled Unicode Character in Inline Content-Disposition Crashes Server with ERR_INVALID_CHARIMPLEMENTATION_DEFECTOPEN

backend/src/controllers/bookController.js:15-20 · SUSPECTED confidence:

Evidence

res.setHeader('Content-Disposition', mode === 'download' ? contentDispositionFilename(book.filename) : `inline; filename="${cleanFilename(book.filename).replace(/"/g, '')}"; filename*=UTF-8''${encodeURIComponent(cleanFilename(book.filename))}`). cleanFilename retains Unicode codepoints > 255. Node.js OutgoingMessage.setHeader throws TypeError [ERR_INVALID_CHAR].

Impact

Denial of service for reading any non-ASCII or regional-language PDF books.

Reproduction

Create or update a book record with filename 'GeM_मार्गदर्शिका.pdf'. Send GET /api/public/books/<id>/read. The server throws uncaught exception 'ERR_INVALID_CHAR: Invalid character in header content' and fails with 500.

Suggested remediation

Sanitize the legacy filename parameter to ASCII-only alphanumeric characters in inline mode (matching contentDispositionFilename fallback: filename.replace(/[^a-zA-Z0-9._ -]/g, '_')), while providing full Unicode in the RFC 5987 filename*=UTF-8'' parameter.

Regression test

Configure a book with filename 'हिन्दी_गाइड.pdf' and send GET /api/public/books/:id/read. Assert response is HTTP 200 with valid Content-Disposition header.

backend/src/middleware/upload.middleware.js:380-437 · SUSPECTED confidence:

MEDIUMSocket and Stream Resource Leak on Client Connection Abort During PDF DeliveryIMPLEMENTATION_DEFECTOPEN

backend/src/controllers/bookController.js:28-34 · SUSPECTED confidence:

Evidence

streamBook attaches stream.on('error', ...) and executes stream.pipe(res). When a client abruptly terminates or closes the connection during streaming of large 50MB files, res emits 'close', but stream is neither unpiped nor destroyed.

Impact

Socket and memory leaks leading to event-loop lag and connection starvation.

Reproduction

Initiate GET /api/public/books/:id/read, read 32KB, and terminate socket connection. Observe MinIO client stream remains un-destroyed.

Suggested remediation

Replace stream.pipe(res) with pipeline from 'node:stream/promises' or bind res.on('close', () => { if (!res.writableEnded) stream.destroy(); }).

Regression test

Simulate client socket closure during streamBook execution and verify stream.destroyed evaluates to true.
