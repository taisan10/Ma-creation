HIGHUnvalidated Foreign Key References Allow Creation of Orphaned Courses and Inaccessible ContentDATA_INTEGRITY_VIOLATIONOPEN

backend/src/services/course.service.js:73-95 · VERIFIED confidence: HIGH

Evidence

CourseService.createCourse directly creates Course documents with req.body.category and req.body.plan without verifying Category.exists({ _id: category }) or Plan.exists({ _id: plan }).

Scenario

An administrator submits POST /api/admin/lms/courses with an arbitrary 24-character hex string for category or plan (e.g. from a deleted plan or typo). The course is persisted in MongoDB. Because the plan does not exist, no student can ever purchase or unlock the course. Because the category does not exist, course.category is null, causing it to fall into 'uncategorized' or crash frontend views expecting category metadata.

Impact

Data corruption, permanently inaccessible course content, broken curriculum hierarchy, and frontend rendering anomalies.

Reproduction

As admin, send POST /api/admin/lms/courses with { category: '660000000000000000000001', plan: '660000000000000000000002', title: 'Orphan Course' }. Request returns 201 Created and persists an unlinked course.

Suggested remediation

Add existence checks in CourseService.createCourse: const [catExists, planExists] = await Promise.all([Category.exists({ _id: category }), Plan.exists({ _id: plan })]); if (!catExists) throw new AppError('Category not found', 404, 'CATEGORY_NOT_FOUND'); if (!planExists) throw new AppError('Plan not found', 404, 'PLAN_NOT_FOUND');

Regression test

Call createCourse with non-existent category/plan IDs and assert it throws 404 CATEGORY_NOT_FOUND / PLAN_NOT_FOUND.

HIGHNon-Atomic Cascading Deletions Without Transaction Cause Partial Data Loss and Storage DesynchronizationDATA_INTEGRITY_VIOLATIONOPEN

backend/src/services/course.service.js:55-114 · VERIFIED confidence: HIGH

Evidence

deleteCategory and deleteCourse delete MinIO assets via deleteMinioVideoAssets, then call Video.deleteMany and Course.deleteMany without a MongoDB transaction session. Neither method cleans up BullMQ transcode jobs or /tmp/uploads/${videoId} files.

Scenario

An administrator deletes an active course or category. If MinIO asset deletion times out (accumulating thousands of HLS segment keys in memory via listObjects) or throws a network error, MongoDB records remain while video files are partially erased. Furthermore, active transcode jobs in BullMQ are not removed, causing workers to crash when updating non-existent video records. Additionally, students who paid for the associated plan have their paid course content wiped out without warning, confirmation, or audit trail.

Impact

Desynchronized storage state (MinIO vs MongoDB), unhandled background worker crashes in BullMQ, and irreversible deletion of student-paid educational material without audit logging.

Reproduction

Trigger DELETE /api/admin/lms/courses/:id while a video in that course is actively transcoding. The video is deleted from MongoDB, but the BullMQ job continues running and throws an unhandled error upon transcode completion.

Suggested remediation

Wrap multi-collection operations in a MongoDB session transaction (session.startTransaction()). Replicate BullMQ queue cancellation and /tmp/uploads cleanup from deleteVideo into deleteCourse and deleteCategory. Implement soft-deletion (active: false) and verify no active paid entitlements exist before permitting deletion.

Regression test

Execute deleteCourse on a course with pending BullMQ transcode jobs and assert the queue job is evicted, local temp directories are purged, and DB operations rollback on MinIO failure.

backend/src/middleware/requireEntitlement.js:29-37 · VERIFIED confidence: HIGH

Evidence

if (!video) { video = await Video.findOneAndUpdate({ _id: req.params.videoId, status: 'READY' }, { $set: { active: true } }, { new: true }) }

Scenario

An administrator intentionally disables or retracts a video by setting active: false (e.g. copyright notice, outdated content, or quality dispute). When an entitled student requests GET /api/videos/:videoId/key or POST /api/videos/:videoId/playback-token, requireVideoEntitlement detects active: false with status: 'READY' and automatically executes findOneAndUpdate({ $set: { active: true } }), overturning the administrator's deliberate deactivation.

MEDIUMTime-of-Check to Time-of-Use Race Condition in Video Title Uniqueness Allows Duplicate VideosCONCURRENCY_DEFECTOPEN

backend/src/services/course.service.js:132-156 · VERIFIED confidence: HIGH

Evidence

Video title uniqueness is checked using an application-level findOne regex query without a matching unique compound index on { course: 1, title: 1 } in Video.js.

Scenario

Two administrator requests (or double-click submissions) submit the same video metadata simultaneously. Both requests execute the findOne query concurrently before either document is inserted. Both checks pass, resulting in duplicate video entries with identical titles in the course playlist.

Impact

Corrupted curriculum playlists, duplicate transcode jobs, and confused student navigation.

Reproduction

Send two concurrent POST /api/admin/lms/videos requests with identical course and title. Both return 201 Created and two identical video records are created.

Suggested remediation

Add a unique compound index with collation in backend/src/models/LMS/Video.js: schema.index({ course: 1, title: 1 }, { unique: true, collation: { locale: 'en', strength: 2 } }). Catch MongoDB 11000 duplicate key error and return 409 DUPLICATE_TITLE.

Regression test

Execute concurrent video creation requests with identical titles and verify exactly one succeeds and the other fails with 409 DUPLICATE_TITLE.

backend/src/services/course.service.js:233-247 · VERIFIED confidence: HIGH

Evidence

CourseService.listUserCourses groups courses into a Map keyed by category._id in the order courses were returned by Course.find().sort({ order: 1, createdAt: 1 }), completely omitting category.order sorting.

Scenario

Category A has administrative display order 10, and Category B has order 1. If Course 1 under Category A has course order 0 and Course 2 under Category B has course order 1, Course 1 is processed first, inserting Category A into the Map before Category B. Impact

Inconsistent, non-deterministic category ordering on the student LMS dashboard.

Reproduction

Sort the final grouped array before returning: return Array.from(grouped.values()).sort((a, b) => (a.category?.order ?? 9999) - (b.category?.order ?? 9999));

Regression test

Call listUserCourses with multi-category courses and verify categories are sorted strictly ascending by category.order.
