Technical Deep-Dive: The 4 Strategic Phases

Step-by-step architectural breakdown of encoding, security barriers, streaming, and telemetry.

PHASE 01 Background Worker

Ingestion, Multi-Bitrate Transcoding & DRM Encryption

When an admin uploads a lecture, it bypasses main API threads directly to the transcode worker pool. The worker manages resource limits and performs on-the-fly encryption.

  • Cryptographic Key Generation: Generates a cryptographically strong 16-byte AES key + 16-byte IV via Node.js crypto.randomBytes(16).
  • Single-Pass Multi-Output ABR: Uses FFmpeg's split=2 filter complex to encode 1080p, 720p, and 360p simultaneously, eliminating double-decode CPU overhead.
  • HLS Chunk Encryption: Video is sliced into 6-second segments (-hls_time 6) with individual AES-128 CBC locks.
  • Zero-Leakage Upload: Only encrypted .ts and .m3u8 files are pushed to MinIO S3. The raw key (enc.key) is strictly blocked from S3.
PHASE 02 API Gateway

Entitlement Gatekeeping & Playback Token Handshake

Students cannot directly download or load video files. Every view request must pass through multi-layer authorization checks before a single byte of video is served.

  • Course Ownership Check: Validates MongoDB Payment collections to ensure the user has a verified, paid order for the course's linked plan.
  • Anti-Recording Lock Check: Rejects playback if the user has active screen capture strikes (playbackLocked: true).
  • Watch Multiplier Quota: Compares cumulative watch history in WatchLog against duration * multiplier. Prevents credential-sharing abuse.
  • Short-Lived Token: Issues a unique UUID playback token with a strict 360-second TTL saved in MongoDB's PlaybackSession.
PHASE 03 Client Player (Web/Flutter)

Stream Negotiation, In-Memory Decryption & GPU Decode

Decryption and decompression happen completely inside the student's device hardware memory, preventing IDM or file-ripper extensions from extracting clean video files.

  • Adaptive Bitrate (ABR): Player inspects network bandwidth and switches seamlessly between 1080p, 720p, and 360p without pausing or buffering.
  • In-Memory Key Delivery: The player fetches the 16-byte AES key via GET /api/videos/:id/key. The key is held strictly in volatile RAM, never written to disk.
  • Chunk-by-Chunk Decryption: As 6-second .ts chunks arrive from MinIO, the player decrypts them in memory using the AES-128 key.
  • Hardware GPU Decoding: The decrypted H.264 stream is handed off directly to native device hardware decoders (Apple VideoToolbox / Android MediaCodec / NVDEC) for smooth 60fps rendering.
PHASE 04 Live Telemetry

Watch Quota Enforcement & Anti-Piracy Defense

Continuous real-time communication between the player and server ensures that stream sharing, bot scraping, and excessive viewing are neutralized in real time.

  • Heartbeat Telemetry: Every 15-30 seconds, player posts timestamp and duration watched to POST /api/videos/:id/watch-event.
  • Strict Session Binding: Each heartbeat requires matching PlaybackSession.token, ensuring an expired or stolen session cannot continue playing.
  • Instant Revocation: If watch time reaches the plan limit, backend throws WATCH_LIMIT_REACHED, instantly cutting off subsequent chunk decryption.
  • Screen Capture Defenses: Browser blur events and recording strikes flag SecurityIncident for admin review.

Core Concepts: Encoding vs. Encryption vs. Decryption vs. Decoding

Clear distinction between video compression and DRM security layers.

1
Video Encoding / Transcoding

Compresses raw video pixels into efficient formats (H.264 / AAC) and creates multiple resolutions (1080p, 720p, 360p) for smooth internet streaming.

Goal: File Size & Speed
2
DRM Encryption (AES-128)

Scrambles each 6-second video chunk with a unique 16-byte cryptographic key. If downloaded via IDM or URL, the file is unreadable static.

Goal: Piracy Protection
3
In-Memory Decryption

The authorized video player loads the 16-byte key into volatile RAM and unscrambles each chunk in real time right before playing it.

Goal: Safe Delivery
4
Hardware Video Decoding

The user device's physical GPU uncompresses the decrypted H.264 video stream into raw RGB pixels and renders them to the screen canvas at 60fps.

Goal: Screen Rendering
